Before Beginning

About R Markdowns

Before we dive into this project and question, let’s get acquainted with what this file is. We are using an R Notebook. An R Notebook has code chunks that can be executed independently and interactively, with the output visible immediately beneath the input. Notebooks are useful for data science projects because they allow us to have code, the results of the code, and our own notes all in one place.

In an R Notebook, notes are in white and code chunks are in grey boxes like the one below:

print("This is a code chunk")
## [1] "This is a code chunk"

When you run a code chunk, the results from the code show up below the code chunk it came from.

You can click the green play button at the top right of these code chunks to run an individual code chunk, or you can click the run button at the top of this whole window if you want to run specific code chunks.

Creating a new code chunk

You can create a new code chunk by typing it by hand or by clicking the green C button for insert new code chunk at the top of this window.

# Note that if I start a line with a '#' then what I right after it is ignored by R.

Code needs to be within the grey code chunks to be run. Anything outside of the code chunks is notes. We can see the difference between code and text (notes) as the code chunks are in grey and the text (notes) are in the white space.

Tips for Using Code Chunks

  • No nested chunks: Don’t place a chunk inside another, this will cause errors.

  • Add spacing: Leave a blank line before and after each chunk to separate it from surrounding text.

  • Close chunks properly: Every chunk must end with three backticks (```). This signifies the end of code and begining of text. You can only see these backticks when viewing this document as source rather than visual.

  • Only write code in chunks: Use # for comments. Text that’s not valid R code must go outside the chunk.

These common issues often cause rendering problems, keep chunks clean and clearly separated from text.

Getting the data

To begin our analysis, we need to load the data. We’ll be reading a CSV file named candy-data.csv, which is located in the data folder of our project. This file contains survey responses where people rated different types of Halloween candy.

To load this dataset into R and assign it to an object called candy_df, we can run the following code chunk:

candy_df <- read_csv(file.path("data", "candy-data.csv"),
                     show_col_types = FALSE)

This code reads the contents of the CSV file namedcandy-data.csv and stores it in a data frame object (specifically, a tibble) named candy_df.

Breaking it down

  • candy_df <-: Create a new object called candy_df and assign <- output to this object

  • read_csv(...): A function from the readr package (part of the tidyverse).

    • It reads a CSV file into a tibble (a modern version of a data frame in R).

  • file.path("data", "candy-data.csv"): Safely constructs a file path.

    • Combines “data” and “candy-data.csv” into a proper path like “data/candy-data.csv”.

  • show_col_types = FALSE: This suppresses the message that normally shows column types when reading the CSV.

Plotting the data

We will be using the ggplot2 visualization to create a bar chart showing the most popular candies based on their win percentage (using the winpercent column). It is a measure of how often a candy was preferred over another in some sort of match-up or ranking system.

In this exercise we want to create a bar chart ranking candies by how often they were preferred. The taller bars will indicate which candies are more popular. We will have it color-coded by whether the candy contains chocolate (based on true or false statements) and we will sort it from most to least popular (left to right).

ggplot(candy_df, aes(x = reorder(competitorname, -winpercent), y = winpercent, fill = chocolate)) +
  geom_bar(stat = "identity") +
  ggtitle("Most popular candies") +
  theme_bw() +
  theme(axis.text.x = element_text(angle = 90, vjust = 0.5, hjust=1)) +
  xlab("") +
  ylab("Win percentage")

Breaking it down

  • ggplot(candy_df, aes(...)): Starts building the plot using the dataset candy_df.

    • aes(): defines the aesthetics: what goes on the x-axis, y-axis, and how to color the bars.

  • x = reorder(competitorname, -winpercent): Reorders the data so that the most popular candies (highest win percent) are on the left.

    • competitorname: refers to the name of each candy

    • reorder(...): orders the candies

    • -winpercent: indicates to order from highest to lowest win percentage (due to the negative sign - before winpercent).

  • y = winpercent: The height of each bar represents the candy’s win percentage.

  • fill = chocolate: Fills the bars with different colors based on whether the candy contains chocolate (TRUE or FALSE).

    • This allows us to visually compare chocolate vs. non-chocolate popularity.

  • geom_bar(stat = "identity") Creates the actual bars.

  • stat = "identity” tells ggplot2 to use the winpercent values directly (not counts).

  • ggtitle("Most popular candies") Adds a title to the plot.

  • theme_bw() Applies a clean black-and-white theme.

  • theme(axis.text.x = element_text(...)) Rotates the x-axis labels 90 degrees so the candy names are readable.

    • vjust and hjust adjust the alignment for clarity.

  • xlab("") Removes the x-axis label (making it optional, since candy names are self-explanatory).

  • ylab("Win percentage") Sets the y-axis label.

Interpreting the plot

This plot shows that Reese’s Peanut Butter Cups had the highest win percentage, making it the most popular candy in the dataset. We also color-coded the bars based on whether or not each candy contains chocolate. From the chart, it appears that chocolate candies tend to have higher win percentages overall. This suggests that, in general, chocolate candies are more popular than non-chocolate ones among survey respondents.

Streamlining our workflow

We will also be using the magrittr package, which gives us the pipe operator %>%.

The pipe pipe operator %>% helps us write code that flows so we can chain steps together in a clear, readable way. Allowing us to run multiple sequential functions in one code chunk.

Now that we have seen the data visualized in the bar plot let’s re-frame our initial research question (What’s the most popular Halloween candy?) from a data science analysis point of view to form our next question:

Are chocolate candies more popular than non-chocolate candies?

In the second part of this project, we’ll also want to test the hypothesis:

Chocolate candies have a higher win percentage than non-chocolate candies.

To begin answering this question, we will group the candy dataset according to whether or not each candy contains chocolate, and then calculate the average win percentage for each group.

We can calculate the average win percentage for each group (chocolate vs. non-chocolate) using the code chunk below:

# First we can just use averages to see what the differences are!
 candy_df %>%
  group_by(chocolate) %>%
  summarize(ave_winpercent=mean(winpercent))

Breaking it down

  • candy_df: This is the data frame object containing information about various candies including their names, win percentages, and whether they contain chocolate.

  • %>%: This is the pipe operator from the magrittr package

    • We could run each function separately, but that would be extra lines of code. Since we only want the final result, not the intermediate outputs we can use a pipe %>% which will run a sequence of functions on a single object. This takes the output of the first function as the input for the next function and so on. You can read it like “and then pipe.”

  • group_by(chocolate): This tells R to group the data into two categories:

    • Candies that contain chocolate (TRUE)

    • Candies that do not contain chocolate (FALSE)

  • summarize(ave_winpercent=mean(winpercent)): For each group, this calculates the average (mean) of the winpercent column. It returns a small summary table with:

    • One row for chocolate = TRUE

    • One row for chocolate = FALSE

    • A column with the name ave_winpercent showing the average win percentage for each group

Hint: This is how you would read this code step by step: Start with the candy_df dataset and then pipe (%>%) the data into group_by(chocolate) (which splits the data into two groups based on whether or not a candy contains chocolate) and then pipe the grouped data into summarize(mean(winpercent)), which calculates the average win percentage for each group.

Note: This code doesn’t assign the result to a new object yet. It is just printing the summarized data.

Calculating the stats

At first glance, based on percentages it seems obvious that 60% is bigger than 42% but is that difference statistically significant? In data science, we can use statistical methods to help answer questions like this.

We think chocolate candies are more popular than non-chocolate ones but how can we be sure the difference isn’t just by chance?

You can run a t-test. This is a common statistical method used to compare the averages (means) of two groups. In our case, we are comparing chocolate vs. non-chocolate candies. To figure out if the difference we see (60% vs. 42%) is actually statistically significant you can run the code chunk below:

chocolate <- filter(candy_df, chocolate) %>%
  pull(winpercent)

not_chocolate <- filter(candy_df, !chocolate) %>%
  pull(winpercent)

t.test(chocolate, not_chocolate,
         alternative = "greater")
## 
##  Welch Two Sample t-test
## 
## data:  chocolate and not_chocolate
## t = 7.3031, df = 67.539, p-value = 2.082e-10
## alternative hypothesis: true difference in means is greater than 0
## 95 percent confidence interval:
##  14.49083      Inf
## sample estimates:
## mean of x mean of y 
##  60.92153  42.14226

Breaking it down

  • chocolate <-: Create a new object called chocolate and assign <- output to this object

  • filter(candy_df, chocolate): Filters the dataset to keep only rows where the chocolate column is TRUE (i.e., candies that contain chocolate).

  • %>% : Passes the dataset into the next function (pull).

  • pull(winpercent): Extracts (or “pulls out”) just the winpercent column from those filtered rows.

  • not_chocolate <- Create a new object called not_chocolate and assign <- output to this object

  • filter(candy_df, !chocolate): Filters the dataset to keep only rows where the chocolate column is FALSE ! (i.e., candies that do not contain chocolate).

  • %>%: Passes the dataset into the next function (pull).

  • pull(winpercent): Extracts (or “pulls out”) just the winpercent column from those filtered rows.

  • t.test(chocolate, not_chocolate, alternative = "greater"):

    • t.test(``chocolate, not_chocolate: Runs a t-test to compare the average win percentages between chocolate and non-chocolate candies.

    • alternative = "greater" indicates that we are conducting a one-sided hypothesis test (one directional: Is the mean win percentage of chocolate candies greater than that of non-chocolate candies?)

This code compares the win percentages of chocolate vs. non-chocolate candies. The alternative = "greater" argument indicates that our hypothesis is directional. We’re specifically testing whether chocolate candies have a greater win percentage.

The result includes a p-value, the p-value tells us the probability that the difference in win percentages is just random. We will learn more about this later, for now, what we need to know is:

A small p-value (typically less than 0.05) means the difference is probably real.

In our case he p-value is very small (p = 0.0000000002082 which is much smaller than 0.05!), so we can confidently say: Chocolate candies really are more popular than non-chocolate candies in this dataset. This means the difference between chocolate (60%) and non-chocolate (42%) is statistically significant, not due to random chance.
